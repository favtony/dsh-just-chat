# 侧栏统一滚动与异常回退修复方案

## 背景

插件接管 DSH 的 `sidebar.workspaces` 官方入口，把“工作区”和插件生成的“对话”放入同一个侧栏区域。最近一次侧栏滚动调整把两个分区改成了 `flex: 0 0 auto`，导致官方 WorkspaceBrowser 依赖的高度传递失效，展开侧栏时可能出现工作区区域塌缩，最终表现为左侧导航为空。

## 目标

- 保留“工作区”和“对话”在同一个外层滚动区域中的行为。
- 正常情况下继续复用 DSH 官方 WorkspaceBrowser、搜索、菜单和列表交互。
- 展开侧栏时，如果工作区区域尺寸异常，自动停止插件侧栏布局并恢复官方组件。
- 插件组件发生渲染异常时恢复官方组件，避免整个 `sidebar.workspaces` 插槽变成空白。
- 回退后停止插件专属的刷新、订阅和投影逻辑。
- 不修改当前 DSH 实例、profile、进程或已有用户数据。

## 实现方案

### 1. 一个外层滚动容器

插件根节点保留 `display: flex`、`flex: 1`、`flex-direction: column`、`min-height: 0` 和 `overflow-y: auto`。工作区和对话分区改为自然高度的非伸展项目：

```text
flex: none;
display: block;
```

这样两个分区按内容顺序排在一起，由插件根节点统一滚动；不会恢复成两个各自占据一半空间的滚动面板。

### 2. 只在插件启用期间调整官方列表

官方 WorkspaceBrowser 内部的列表默认使用 `flex: 1` 和 `overflow-y: auto`。插件启用时通过带有 `data-dsh-just-chat-sidebar` 前缀的 CSS，将两个官方浏览器的树列表改为自然高度并关闭内部滚动。样式只在插件布局挂载期间存在，回退或卸载时移除，不影响官方回退界面和其它 DSH 页面。

### 3. 展开状态尺寸保护

只在 `wide === true` 时进行检查。等待两帧以避开展开动画，然后用 ResizeObserver 和后续动画帧检查：

- 插件侧栏根节点有有效宽度和高度；
- 工作区分区有有效宽度和高度；
- 工作区树列表存在并有非零高度；
- 空工作区也必须保留可见的官方空状态区域。

连续三次检查失败才触发回退，避免动画期间短暂的零尺寸误判。一旦回退，本次页面挂载期间不再重新启用插件布局。

### 4. 渲染异常回退

用 React Error Boundary 包住插件布局。插件布局或官方组件适配参数发生运行时异常时，边界直接渲染保存下来的官方 WorkspaceBrowser，并记录警告。官方组件本身的回退渲染不再经过插件投影。

### 5. 回退后的副作用

插件专属的会话记录刷新和本地投影只存在于插件布局子树中。布局回退后该子树卸载，相关刷新、订阅和过滤逻辑随之停止，官方组件重新读取原始 DSH 数据。

## 测试

- 测试有效尺寸和零尺寸判定。
- 测试工作区与对话分区均保持非伸展布局标记。
- 测试尺寸保护只在展开状态生效。
- 测试连续异常触发回退，且回退后不会重复启用插件布局。
- 测试插件渲染异常时保留官方组件回退路径。

## 验证边界

验证命令只使用插件仓库规定的隔离 profile 入口。不得手工修改 `DSH_HOME` 或 `DSH_AGENTS_HOME` 后启动 DSH，也不得操作当前正在使用的 DSH Web 实例。隔离目录清理需要先展示规范化绝对路径和 owner token，再取得用户确认。
